# Атлас

Карта поездок: глобус, маршруты по городам, заметки с фото.
Владелец входит по паролю и редактирует. Все остальные видят публичную версию только для просмотра.

## Запуск у себя

```bash
npm install
cp .env.example .env.local    # впишите ADMIN_PASSWORD, остальное можно оставить пустым
npm run dev                   # http://localhost:3000
```

Без `DATABASE_URL` данные хранятся во встроенной базе в папке `.data`, ничего ставить не нужно.
При первом запуске атлас заполняется демо-поездками. Нужен Node.js 20.9 или новее.

Чтобы войти: «Ещё» → «Вход для владельца» → пароль из `ADMIN_PASSWORD`.

## Как устроены права

| | Гость | Владелец |
|---|---|---|
| Смотреть публичные поездки | ✓ | ✓ |
| Видеть скрытые («Кто видит: Только я») | — | ✓ |
| Добавлять, править, удалять, грузить фото | — | ✓ |
| Ссылка на поездку | ✓ (публичные) | ✓ |
| Карточка PNG | ✓ (публичные) | ✓ |
| Видео-пролёт MP4 | — | ✓ |
| Бэкап и восстановление | — | ✓ |

Права проверяет сервер, а не интерфейс: без входа API отвечает 401 на любое изменение.

## Поделиться поездкой

Кнопка «Поделиться» в шапке поездки:

- **Ссылка** вида `/t/yaponiya-2025` открывает атлас сразу на поездке. В Telegram у неё появится превью с маршрутом.
- **Видео-пролёт.** Камера летит по городам, маршрут прорисовывается, на остановках выезжают карточки с фото. Ролик собирается прямо в браузере (Chrome, Edge, Safari 17+), длится 10–30 секунд. В Telegram беззвучное MP4 крутится как гифка. На телефоне кнопка «Отправить» открывает системное меню, где есть Telegram. Пока ролик собирается, вкладку не сворачивайте.
- **Карточка** — постер 1080×1350 с обложкой, маршрутом и списком городов.

## Деплой: GitHub + Vercel + Neon (бесплатно)

### 1. GitHub

```bash
git remote add origin git@github.com:ВАШ_ЛОГИН/atlas.git
git push -u origin main
```

Репозиторий можно делать приватным — Vercel с ним работает. В git не попадают
`.env.local`, папка `.data` (локальная база) и `node_modules` — это настроено в `.gitignore`.

### 2. База Neon

Проще всего прямо из Vercel: проект → **Storage → Create Database → Neon** →
регион Frankfurt (или ближайший к вам) → Connect to project. Vercel сам добавит
переменную `DATABASE_URL` во все окружения.

Или вручную на [neon.tech](https://neon.tech): создать проект → Connect →
включить **Connection pooling** → скопировать строку
(`postgresql://…-pooler….neon.tech/neondb?sslmode=require…`) и вставить в `DATABASE_URL`.

Таблицы создаются сами при первом открытии сайта. Атлас на проде стартует **пустым**
(демо-поездки только локально; если они нужны и на проде — `SEED_DEMO=1`).

### 3. Vercel

Import Project → выбрать репозиторий. Framework определится как Next.js,
команды сборки менять не нужно. Перед Deploy — **Environment Variables**:

| Переменная | Обязательна | Что вписать |
|---|---|---|
| `ADMIN_PASSWORD` | да | пароль владельца, 12+ символов |
| `SESSION_SECRET` | да | случайная строка: `openssl rand -base64 32` |
| `DATABASE_URL` | да | строка Neon (pooled). Если база подключена через Storage — уже есть |
| `SITE_URL` | нет | свой домен, если подключите: `https://atlas.example.com` |
| `SEED_DEMO` | нет | `1` — заполнить пустую базу демо-поездками |

Ставьте переменные для **Production** (и Preview, если пользуетесь превью-сборками).
После изменения переменных нужен **Redeploy** — сами они в работающий сайт не подтянутся.

Без `DATABASE_URL` сайт на Vercel покажет понятную ошибку: встроенная база там
не работает, диск у Vercel временный.

### 4. Проверка после деплоя

1. Открыть сайт → «Ещё» → «Вход для владельца» → пароль.
2. Добавить место, заметку с фото.
3. «Поделиться» → «Открыть доступ всем» → скопировать ссылку и вставить в Telegram —
   должно появиться превью с картой.

Если превью в Telegram не появилось с первого раза — Telegram кеширует ссылки;
отправьте ссылку боту [@WebpageBot](https://t.me/WebpageBot), он обновит превью.

### Что ещё важно знать

- **Смена пароля:** поменяйте `ADMIN_PASSWORD` в Vercel → Redeploy. Чтобы заодно
  разлогинить все устройства, поменяйте и `SESSION_SECRET`.
- **Фото** хранятся в той же базе (до 4 МБ каждое, браузер ужимает их перед загрузкой).
  Бесплатных 0,5 ГБ у Neon хватит примерно на 1–2 тысячи снимков.
- **Бэкап:** «Ещё» → «Данные» → «Скачать бэкап» (поездки и заметки; фото остаются в базе).
  Плюс у Neon есть точки восстановления базы.
- **Регион:** Vercel → Settings → Functions → Region — выберите тот же, что у базы
  (например, Frankfurt `fra1` для Neon `eu-central-1`), так сайт отвечает быстрее.
- **Тесты в GitHub** запускаются сами на каждый push (вкладка Actions). Деплой от
  них не зависит — Vercel собирает сайт параллельно.

## Деплой: свой сервер (VPS)

```bash
ADMIN_PASSWORD=ваш-пароль docker compose up -d
```

Поднимутся приложение и Postgres. Сверху нужен HTTPS (например, Caddy), иначе на телефоне не заработают «Поделиться» и вход.

## Перенос данных из HTML-превью

В превью: «Ещё» → «Скачать бэкап». Здесь: «Ещё» → «Данные» → «Восстановить из бэкапа».
Фото, загруженные в превью, жили только в браузере и не переносятся. Их нужно загрузить заново.

## Тесты

```bash
npm test             # логика, база, API и интерфейс (Vitest) — около минуты
npm run test:e2e     # сквозные сценарии в настоящем Chromium — 5–7 минут
npm run test:all     # типы + всё вышеперечисленное
```

Перед первым `test:e2e` один раз скачайте браузер: `npx playwright install chromium`.
В GitHub тесты запускаются сами на каждый push (`.github/workflows/test.yml`).

**Что проверяется:**

- **Логика** (`tests/unit`): адреса поездок, склонения, проверка входящих данных, подпись и срок сессии, лимит попыток входа, разбор ссылок Google Maps, импорт старых бэкапов, сценарий камеры видео (плавность, все города, линия перемены дат), отрисовка кадров ролика.
- **База** (`tests/db`): встроенный Postgres и настоящий драйвер `postgres.js` по сети — схема, демо при первом запуске, адреса без дублей, транзакции с откатом, каскадное удаление, видимость скрытых поездок, хранение фото и их уборка.
- **API** (`tests/api`): права гостя и владельца на каждом маршруте, защита от запросов с чужих сайтов, валидация, загрузка фото (подмена типа, размер), разворот коротких ссылок без выхода за пределы Google, карточки PNG и OG-превью.
- **Интерфейс** (`tests/components`): формы, панели в режиме гостя и владельца, шаринг, добавление мест, сохранение на сервер с «Отменить», откат при ошибке сети, очередь сохранений, шторка (быстрые тапы, свайпы, клавиатура).
- **E2E** (`e2e`): полный путь в браузере против собранного сервера — гость, вход, скрытые поездки, заметка с фото, публикация, удаление с отменой, бэкап, выход. Плюс **настоящая сборка видео-пролёта**: проверяется, что получился проигрываемый MP4 H.264 720×900 нужной длины с маршрутом и текстом в кадре. Тайлы карты, геокодер и Unsplash в тестах подменяются, интернет не нужен.

## Где что лежит

- `app/api/` — API: вход, поездки, фото, карточка, разворот коротких ссылок Google Maps
- `lib/trips-repo.ts`, `lib/db.ts` — база (Postgres или встроенная)
- `lib/auth.ts` — сессия владельца
- `lib/card.tsx` — карточка и превью ссылки
- `lib/export-video.ts` — видео-пролёт
- `components/` — интерфейс
